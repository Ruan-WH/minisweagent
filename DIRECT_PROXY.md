# Direct source-grounded proxy pilot

The current pilot uses `deepseek-flash` for **all** roles: repair agent, pre-repair clarification checker, reporter generation and grounding review. It uses `hidden_deepseek_flash` from local ignored `config.toml`. Historical Qwen experiments and old runners remain unchanged.

The reporter receives only original issue text, original discussion/hints, public Q/A and the current question. It does not receive semantic rule tables, annotated fact IDs, gold patches, hidden tests, prior solver answers, file-location metadata or official evaluation feedback. Initial partial Q/A remains fixed. Subsequent replies are generated naturally; no per-instance answer templates are used.

Controls:

- Internal JSON has `answer` plus exact `source_quotes`; only `answer` reaches the checker/solver. References are generated by the model and checked against source substrings; they require no human fact labeling.
- Code quotations must be verbatim source substrings. Repaired parentheses, invented parameters or synthesized reproduction code are rejected.
- The prompt restricts replies to requested observations and outcomes, distinguishes successful and failing steps, and forbids diagnosis/fix speculation. A generic lexical guard also rejects explicit causal/internal-mechanism language. This is a coarse gate, not a semantic proof, and may reject legitimate causal wording in other tasks.
- Every locally valid candidate receives a separate grounding-review call with the same model. A rejected or invalid candidate gets at most one correction. Two candidates maximum; no account/transport retry. Reviewer false positives remain possible and were observed with Qwen during development; do not describe this as guaranteed grounding.
- All candidate and review calls, including rejected ones, are retained and counted separately from the solver budget.
- The legacy clarification loop and its semantic prompting remain unchanged. For this pilot only, evidence matching additionally ignores Markdown fence language/info labels (`python` vs `pycon`) and whitespace. Code bodies, arguments, punctuation and factual words must still match. This avoids copying errors without accepting semantic paraphrases as literal evidence.
